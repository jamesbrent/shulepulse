5. SUBSCRIPTION & BILLING ARCHITECTURE
================================================================================

5.1 PLAN DEFINITIONS
---------------------------------------------------------------------------
Plan          Monthly Price (KES)    Source
---------------------------------------------------------------------------
Basic         2,500                  Hard-coded in subscriptionService.js
Pro           5,000                  Hard-coded in subscriptionService.js
Enterprise    10,000                 Hard-coded in subscriptionService.js

Also defined in: PlanChangeModal.jsx, BillingPage.jsx, SchoolDetailModal.jsx (inline ternary)

5.2 DATABASE SCHEMA
---------------------------------------------------------------------------
schools.plan              TEXT, default 'basic'     (007_schools_rls_policies.sql)
schools.billing_cycle     TEXT, default 'monthly'   (010_subscription_columns.sql)
schools.subscription_start  TIMESTAMPTZ             (010)
schools.subscription_end    TIMESTAMPTZ             (010)
schools.auto_renew        BOOLEAN, default true     (010)

plans (reference table):
  id, key, label, price_label, features (JSONB), color, bg, recommended, sort_order
  Created in 006_reference_data.sql with 3 rows: basic, pro, enterprise

5.3 WHAT EXISTS
---------------------------------------------------------------------------
- MRR calculation in SuperadminDashboard (basic * 2500 + pro * 5000 + enterprise * 10000)
- Plan badges on schools list and detail modals
- "Change Plan" modal (updates schools.plan, resets subscription_start, logs audit)
- Subscription stats endpoint (fetchSubscriptionStats - groups schools by plan)
- Upcoming renewals endpoint (fetchUpcomingRenewals - schools expiring within N days)
- Onboarding loads plans from DB reference table
- Plan distribution pie chart in superadmin dashboard
- Revenue by plan bar chart

5.4 WHAT IS MISSING (NO ENFORCEMENT)
---------------------------------------------------------------------------
- No DB constraint on schools.plan (free text, can be any value)
- Plan duplicated in 4+ places (no single source of truth)
- SchoolDetailModal: Renew/Upgrade/Downgrade buttons have NO onClick handlers (decorative)
- SchoolDetailModal: Module toggles are display-only (no enable/disable handler)
- Platform settings: trial_duration_days, grace_period_days, auto_suspension saved but NEVER enforced
- No feature gating based on plan (all schools see all features regardless of plan)
- No payment collection system (no invoices, no M-Pesa integration, no payment links)
- No trial period logic
- No grace period logic
- No auto-suspension when subscription expires
- No email/SMS notifications for renewals
- modules_config column exists but is NOT checked before rendering features
- 'plan' column has no CHECK constraint - any text value accepted
